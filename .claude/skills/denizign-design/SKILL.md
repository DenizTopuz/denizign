# Denizign Design Skill

Use this skill whenever designing, implementing, reviewing or modifying visual parts of the Denizign portfolio.

The portfolio communicates:

**From complexity to clarity.**

## Required context

Before making meaningful visual decisions, read:

- `/brand/brand-foundation.md`
- `/brand/colors.md`
- `/brand/typography.md`
- `/brand/imagery.md`
- `/brand/motion.md`
- `references/design-system.md`

These files are the source of truth.

Do not create design rules that conflict with them.

## Source hierarchy

Follow the source hierarchy defined in `/CLAUDE.md`.

This skill applies the brand and design system. It does not override them.

For approved brand values, `/brand/` is authoritative.

## Design character

The interface should feel:

- minimal
- calm
- intelligent
- editorial
- architectural
- premium
- human
- confident

The portfolio should feel appropriate for a UX Lead and systems thinker.

It should not feel like:

- a generic freelance portfolio
- a SaaS landing page
- an AI-generated template
- a decorative design agency website

## Visual principles

### Clarity

Use strong hierarchy.

Prefer whitespace over decorative containers.

Reduce visual noise.

Use one primary message per section.

### Connection

Use layout, alignment, sequencing and subtle motion to communicate relationships between:

- users
- experience
- product
- technology
- systems
- organisation

Avoid generic network diagrams.

### Layers

Layers may communicate different parts of a product or system.

They should organise into a clear whole.

Do not use layers only as decoration.

## Typography

Use:

- Manrope for headings
- Inter for body copy and UI

Typography and whitespace should do most of the visual work.

## Colour

Use only the approved Denizign palette.

Red is the only strong accent colour.

Use it sparingly.

Never introduce another accent colour without explicit approval.

## Logo

Use website assets from:

`/brand/logo/web/`

Never recreate the logo with CSS or redraw it.

Never alter its geometry.

## Components

Prefer:

- clean grids
- strong typography
- generous spacing
- restrained borders
- subtle interactions

Do not turn every piece of content into a card.

## Motion

Use the Denizign motion principle:

**Fragment → Connect → Organise**

Motion should communicate complexity becoming clarity.

Do not animate elements purely for decoration.

## Case studies

Use:

**Problem → Thinking → Intervention → Outcome**

Case studies should explain reasoning and decisions, not only show final screens.

## Responsive design

Design mobile-first.

Do not simply shrink desktop layouts.

Check desktop, tablet and mobile after meaningful visual changes.

## Accessibility

WCAG 2.2 AA is the minimum standard.

Maintain:

- semantic structure
- strong contrast
- keyboard accessibility
- visible focus
- accessible touch targets
- reduced motion
- correct heading hierarchy

## Design review

Before considering a visual implementation complete, review:

- hierarchy
- typography
- spacing
- alignment
- colour usage
- responsiveness
- accessibility
- brand consistency

Always ask:

**Does this make the experience clearer?**

If not, simplify it.
